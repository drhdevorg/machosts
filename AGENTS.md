## Workflow for each coding run

- Complete as many related steps and, when gates permit, multiple phases as possible in one run. A general “continue coding” means continue within the agreed project scope rather than stopping after a small isolated fix. Explicit scope limits remain binding.
- Batch tests, builds, and formatting after substantial functional milestones rather than every small change. Supply required evidence before crossing a gate. Repair failed checks specifically and rerun appropriate checks.
- First select the largest reasonably completable block; implement related changes and tests together. If blocked, complete independent permitted tasks without bypassing gates. Do not substitute artificial tiny tasks for an unresolved architectural problem.
- Use `rg` for targeted searches, read relevant file ranges, and batch independent reads. Do not repeatedly dump unchanged instructions in the same context. Write lengthy check output to local logs and report results or relevant errors only.
- Reuse existing solutions and system frameworks. Avoid speculative abstractions, unnecessary dependencies, and unrelated refactors. Prioritize behavior/contract tests rather than tests mirroring internals.
- Use incremental builds and existing caches. Repeat successful checks only for relevant changes or unresolved risks; verify documentation-only edits directly without app builds/tests.
- Make routine decisions independently, give concise progress updates, and update status/evidence together after substantial milestones. Report changes, actual checks, and remaining blockers briefly at the end.

Claim tests, features, and production readiness only with actual evidence. Keep phase status and `docs/verification/phase-N.md` current during implementation. Do not start subagents without an explicit request.
